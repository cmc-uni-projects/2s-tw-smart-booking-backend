# Mission: Own the Smart Booking System codebase (backend + frontend)

> ⚠️ DRAFT — written by the teacher from the first request ("overview the 2 project sources"). Confirm or correct it; every future lesson is steered by this file.

## Why
Be able to work confidently in the TravelMate / Smart Booking System — explain how it works end-to-end, change features without breaking the money path (booking → payment → refund), and defend design decisions (e.g. in a project review or when continuing development).

## Success looks like
- Explain, without notes, the path of a request from a React page to the MySQL row and back.
- Draw the Booking and Payment state machines and name the endpoint behind every transition.
- Locate the code for any feature in under a minute (controller → service → repository / page → service.js).
- Run both apps locally and make a real end-to-end booking.
- Fix at least one item from [docs/07-gotchas-and-risks.md](./docs/07-gotchas-and-risks.md) (e.g. ownership checks) with confidence.

## Constraints
- Lessons and docs are Markdown files kept in `2s-tw-smart-booking-backend/.claude/` (user request).
- Short lessons — one tangible win each.

## Out of scope (for now)
- Rewriting the architecture, migrating to TypeScript, DevOps/CI design.
